# SDD-метод проекта (локально, в git не едет)

> Spec-Driven Development в нашем урезанном виде: спека — это тест + запись
> в todo, а не отдельный документ. Источник: https://specdriven.ai/
> (разбор 11.10). Полный ритуал specdriven.ai (генерация кода из спеки,
> шаблоны constitution/spec/plan/tasks) НЕ берём — он задвоил бы AGENTS.md
> и противоречит MUST «TDD сначала». Берём только mapping ниже.

## Mapping фаз на наши артефакты

| SDD-фаза | Наш артефакт (единственный дом для неё) |
|---|---|
| Constitution | `AGENTS.md` — выше любого плана; противоречие = стоп и вопрос человеку |
| Specify (что и зачем) | NEED-список + точные RU-значения в `test/dfo-<батч>.test.js` ДО кода (конвенция: шапка `// NEED:` в тест-файле) |
| Clarify (снять неоднозначность) | Гейт скилла `skills/ru-localization-qa` + контекст ванили (call-site, note, siblings); сомнения — в ревью-очередь `todo.md`, не в таблицу |
| Plan (как) | Очередь §7 `AGENTS.md` + раздел «Как продолжать» `todo.md`; wiring-принцип (точечный `ruTOr` vs центральный `labelOf`/`railRu`) |
| Tasks (атомарно) | Один батч = одна ветка `feat/<что>`, 1–4 часа, один открытый PR (§5) |
| Implement | TDD RED→GREEN, потом `npm test` + `tools/wire-check.mjs` + `tools/menu-cover.mjs` |
| Verify | 3 уровня из `todo.md`: 1-статика / 2-headless `tmp/dom-probe.cjs` / 3-глаз человека |
| Iterate | Легдер `.superpowers/sdd/<план>/progress.md`, каждая запись — `Ruling:` + цена ошибки (`Cost if wrong:`) |
| Gates | G0–G4 из `todo.md` — чекпоинты перед мержем |

## Чеклист батча (по порядку, пропуск = стоп)

1. Контекст: прочитать call-site'ы ванили + siblings, сверить EN байт-в-байт.
2. Specify: NEED-список и точные RU в тесте, прогнать — RED увиден.
3. Clarify: глоссарий → обратный перевод → регистр → grep-консистентность → плейсхолдеры 1:1 → Ё.
4. Implement: пары в `en.json` + `ru.json`, GREEN (`npm test`, wire-check, menu-cover).
5. Коммит в `feat/<что>`, пуш. Мерж — только по слову человека (G4).
6. Render-proof: маркер в бандле обязателен; headless — если тронут UI; глаз — если экран видимый; остальное — в unwired-list батча, а не «99%».
7. Легдер: `Ruling:` + `Cost if wrong:`; `todo.md`: флажок снят/поставлен сразу.

## Что НЕ делаем (сознательно)

- Отдельных `spec.md`/`plan.md`/`tasks.md` на батч — спека живёт в тесте и todo; исключение: батчи >50 ключей — план-абзац в леджере до кода.
- Ссылки старых леджеров на `docs/superpowers/plans/*.md` — исторические, файлов нет, не чинить.
- Генерации строк AI из спеки без Gate 0–8 скилла (литерализм = баг).
- Нового PR до мержа предыдущего; стеки — только по слову человека, мерж строго снизу вверх.

## Бюджет машины (решение человека 11.10 — беречь компьютер)

Проверка идёт от дешёвого к дорогому, стоп на первом зелёном уровне.
Дорогой уровень без нужды не запускаем.

1. **Статика первее всего**: `npm test` + `wire-check` + `menu-cover` + grep
   маркеров в `dist/assets/*.js`. Это доказывает wiring без единого процесса.
2. **Headless — максимум ОДИН Chrome за раз** (`tmp/chrome-headless.ps1`,
   скрытый + `--mute-audio` + отдельный профиль) и ОДИН preview. Перед
   прогоном — самопроверка: `Get-Process chrome -ErrorAction SilentlyContinue | Measure-Object | Select-Object -ExpandProperty Count` (свой Chrome закрывать не предлагать — считаем только факт). После
   прогона — обязательно гасить оба (`preview-down.ps1` + taskkill по PID
   из `preview.pid`, чужой Chrome не трогать никогда). Новый прогон —
   только после проверки, что старый прибит.
3. **Экран-клики запрещены**: `click-*.ps1`, `shoot-*.ps1` с `CopyFromScreen`,
   foreground-фокус окна игры — не использовать. Скриншоты — только архив
   `tmp/domshots/*.png` из headless-прогона + глаз человека.
4. **Живой Electron — только по прямому приказу**, поштучно, в согласованное
   окно (см. пайплайн H в `todo.md`).
5. Новых `probe-*.mjs`/`click-*.ps1` не плодить: чинить/дописывать
   существующие (`dom-probe.cjs`, `wire-check.mjs`) вместо новых файлов.

## Защита от бесконечных циклов (решение человека 11.10)

Признаки ухода в цикл: повторный прогон неидемпотентного патча
(`ANCHOR GONE`, двойное применение), реран команды с тем же выводом,
третья итерация фикса без смены гипотезы. Правила:

1. **Лимит 3**: один и тот же шаг не повторять больше 3 раз. На третьем
   неуспехе — стоп, записать `Ruling:` с сигнатурой зацикливания и
   переписать план (сменить уровень проверки или гипотезу).
2. **Неидемпотентное — один прогон**: базовые патчи (`anchor→…→menu2→…`)
   гоняются строго один раз в задокументированном порядке; связанность
   проверяется `probe-wired`, а не рераном (урок 7427: реран сломал main.js).
3. **Смена гипотезы обязательна**: повтор с тем же действием запрещён —
   каждый следующий шаг меняет проверяемое предположение и фиксирует его
   в леджере до запуска.
4. **Таймауты**: любая команда с ожиданием — с явным таймаутом (дефолт — 120с); зависший
   preview/headless — гасить по PID, разбираться потом по логам, не ждать.
