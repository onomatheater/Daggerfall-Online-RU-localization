# Лаунчер

Отдельная программа, которая ставит русский перевод и следит за
обновлениями игры. Это Electron-приложение, оно не часть игры.
Игру не качает и не правит. Проверенный пак кладёт в `Prefs/Locale/ru/`
(вне сборки игры — обновление игры его не сносит); после ручного
обновления игры докатывает пак заново. Рецепт-dist остался только
как fallback для версий без Prefs-поддержки.

Файл для тех, кто будет править `updater/`, инструменты паков и фида,
`packs/`. Правила те же, что в `CONTRIBUTING.md`, только про лаунчер.

## Файлы

- `updater/main.js` — окно 960×600, кнопки, скачивание. Тестов на него
  нет (тянет `electron`), поэтому логика должна лежать не здесь, а ниже.
- `updater/lib/flow.js` — вся решающая логика: какой пак подходит,
  установка, баннер новой версии игры, русские тексты ошибок,
  проверка запущенной игры, адрес фида.
- `updater/lib/view.js` — `viewOf()` считает состояние окна. Рисует его
  форкнутый движок разработчиков, он ничего не решает.
- `updater/lib/migrate.js` — разовый переезд `app.asar` в `resources/app`.
  Бэкап чужого файла не затирает. Asar удаляет только после проверки,
  что распаковка цела (ищет `package.json`). Если что-то пошло не так —
  падает с причиной, asar остаётся на месте.
- `updater/lib/dist-apply.js` — кладёт рецепт на распакованную игру:
  проверяет цели удаления, декодит base64, сверяет маркеры и весь контент.
- `updater/lib/asar.js`, `prefs.js`, `unzip.js` — мелочь: версия из asar,
  настройки (папка игры, автопроверка), распаковка zip.
- `updater/launcher/` — форк их окна (MIT, `NOTICE.md` лежит рядом).
  `preload.js` — мост между страницей и шеллом.
- `updater/assets/` — иконка игры и скрипт её сборки.
- `tools/pack-ru.mjs`, `verify-pack.mjs` — собрать пак и проверить его.
- `tools/feed-ru.mjs`, `release-ru.mjs` — фид: выбор пака под версию игры,
  сборка `feed.json` с sha. Битый пак роняет сборку, молча не публикуется.
- `tools/update-ru.mjs`, `pack-store.mjs` — установка и local-стор
  (три последних пака, откат на шаг назад); `installPackToPrefs` кладёт
  проверенный пак в Prefs-локаль (`tools/game-prefs.mjs` — путь userData игры).
- `tools/key-sync.mjs` — очередь синка новых ключей апстрима (без пересборки dist).
- `tools/dist-recipe.mjs` — рецепт как разница двух dist-деревьев.
- `tools/detect-game.mjs` — узнать версию игры.
- `packs/` — то, что раздаётся с `main`: `feed.json` и свежий zip.
  Как выпускать — в `packs/README.md`.

## Фид

Адрес зашит в `updater/lib/flow.js` (`DEFAULT_FEED_URL`), ведёт на
`packs/feed.json` на `main`. Для опытов есть `RU_FEED_URL` с путём
к локальному файлу.

У пака клеймо: точная версия игры (`game`) или пол (`gameMin` — «эта и новее»,
потолка нет: новые ключи честно падают в EN + очередь синка) или отрезок
(`gameMin`–`gameMax`). Ставится новейший подходящий. Нет подходящего —
остаётся английский, это нормально, а не ошибка.

Без валидного sha256 не ставится ничего: ни пак, ни рецепт, ни по сети,
ни локальным файлом. Рецепт только base64. Чужой формат — отказ с причиной.

## Ошибки

Все тексты отказов — в `describeIssue` (`updater/lib/flow.js`), на русском.
Добавил новую причину — добавь перевод и тест в том же коммите.

Одно исключение: неизвестная ошибка показывается как есть, с деталью
(`Не получилось: ...`). Так задумано, тест это проверяет. Не трогать.

`main.js` причины не придумывает, пользуется `restoreFailReason(err)`.

## Сборка

```
cd updater
npm install
npm run dist
```

Выход — установщик NSIS в `updater/release/`, без подписи.
Папка `release/` в git не едет.

`npm run icons` пересобирает иконку, но она уже закоммичена — запускать
надо только если поменялся исходник.

Важно про упаковку: код едет в `app.asar`, а `tools/` и `src/locale/` —
через `extraResources` (рядом, в `resources/tools` и `resources/src`).
Пытаться подсунуть их через `files` с `../` нельзя: в хедере asar
появляются записи `..` и пакет ломается. Уже обжигались 12.10.

Живой запуск окна — только когда owner скажет. Без него проверяем
тестами и разбором собранного пакета.

## Проверка

```
npm test
```

Node 20+. Всё должно быть зелёным.

Новое поведение — сначала падающий тест, потом код. Тест сначала
смотрим красным глазами, иначе он ничего не доказывает.
Проверяемая логика выносится из `main.js` в `lib/`.
Состояния окна проверяет `test/updater-view.test.js`.
