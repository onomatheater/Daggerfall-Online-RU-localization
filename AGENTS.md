## 1. Pay once — качество сразу, без костылей

- MUST: «ID внутри, текст только на рендере». В сеть (`chat`, `trade`, `quest share`), в сейвы и в логику квестов уходят только ключи/ID (`templateId`, `questName`, row-ключи). Локализованная строка никогда не персистится и не отправляется.
- MUST: ключ стабилен. `Key` из `Internal_Strings`/апстрима не переименовывать; переводить только `Value`. Удаление ключа из `en.json` запрещено — только deprecate.
- MUST: разметку не переводить: `[/center]`, `[/record]`, `[/end]`, `%pcn`, `%di`, `%s`, `<-->` остаются как есть; перевод вокруг них.
- MUST: fallback EN. Отсутствующий RU-ключ = английский текст + варнинг в консоль, не `?`, не краш, не пустота.
- MUST: грамматика через ICU + запечённые формы (`{count, plural, one/few/many}`, `{gender, select}`), никаких `if (n==1)` в проде и никакой морфологии в рантайме. Падежи (напр. `15 Января`) — полем словаря, не хардкодом.
- MUST: шрифт из вендора (`vendor/<семья>/`), веса только из разрешённого набора семьи (сейчас: Handjet 400/500/700; Press Start 2P — только 400, других нет). Веса 100/200/300 запрещены (точечный конструкт, нечитаемы). Читаемый минимум пиксельного текста: вес ≥600 (даёт `scale.js` поверх вендорных 400/500/700), кегль ≥14px. Неизвестный глиф → `?` (`FNT_ERROR_CODE`), не пробел-молчание.
- MUST: UTF-8 без BOM во всех `*.json/*.txt/*.csv`; `Ё/ё` обязательна.
- MUST: лицензии шрифтов — только OFL (проверять файл лицензии + сабсет кириллицы парсером, не на глаз). Исключение (напр. CC BY-SA) — только явным решением человека, никогда молча; в апстрим MIT такой шрифт не предлагать без отдельного разбора. Действующее исключение: Guildenstern NBP (CC BY-SA 3.0, решение 10.10, `vendor/guildenstern-nbp/ATTRIBUTION.md`).
- MUST NOT: вендорить шрифты с `personal use` лицензией (напр. Pixel Cyrillic VM Studio).
- MUST NOT: править `QBN:` (логику квестов) в `-LOC` файлах — только `QRC:`.
- MUST: человекочитаемость первее хитрости. Маленькие функции и файлы с одним
  назначением; имена говорящие (`labelOf`, `railRu`, `coverReport`), без
  однобуквенных вне счётчиков циклов; ни одного «умного» хака без комментария
  «почему так» и теста, который его держит.
- MUST: оптимизация один раз (Pay once). Никаких `if (n==1)` в проде — только
  ICU/запечённые формы; никаких вычислений локали на уровне модуля — только
  рендер-тайм; сканы/парсеры — идемпотентные и линейные, с тестом на шум
  (образец: guards в `tools/extract-texts.mjs`, RISK-очередь вместо молчания).
  Покрытие меню держит гвард `tools/menu-cover.mjs`.
- MUST NOT: рефактор ради рефактора. Трогаем только то, что обслуживает текущий
  батч; соседний код улучшаем лишь если он мешает батчу — и тогда это отдельный
  коммит с отдельным тестом.

## 3. Инженерия (TDD обязателен)

- Каждый прод-файл — сначала падающий тест (`node --test test/<name>.test.js`), смотришь RED, потом GREEN, потом коммит. Тест, который не видел RED, не существует.
- Команды: `npm test` (всё; скрипт — `node --test "test/*.test.js"`, голая папка `test/` на Win не резолвится), `node --test test/<file>` (точечно). Node ≥ 20 (import attributes `with { type: 'json' }`).
- Коммиты: `feat(locale): ...`, `feat(font): ...`, `feat(ru): ...`, `fix(...)`. Один таск — один осмысленный коммит минимум; пушить только зелёное.
- Теги: `locale-vX.Y` после каждой завершённой задачи плана.
- Перед PR в апстрим: `npm run check` эквивалент + скрин EN до/после попиксельно совпадает.

## 5. Ветки (main — прод, руками не пушим)

- `main` — прод, только мержи из `dev`. Прямые коммиты и пуш в `main` запрещены.
- `dev` — ветка разработки, в неё мержим готовые фичи после апрува.
- Фичи/фиксы — короткие ветки от `dev`: `feat/<что>`, `fix/<что>`. Закончил → PR в `dev`, апрув → мерж. Пачка в `dev` созрела → PR `dev` → `main` + тег `locale-vX.Y`.
- Перед мержем: тесты зелёные, база подмержена (конфликтующий PR CI не смотрит — сначала мерж базы, потом верификация).
- Patch notes — в описание PR (`## Patch notes: <title>`), файлом в репозиторий не кладём.
- Ветки-стек: новая фича поверх несмерженной — от неё же (`feat/B` от `feat/A`), мерж строго по порядку снизу вверх.
- MUST: один открытый PR на работника за раз (решение человека 11.11: коллаборация — у каждого свой один открытый PR; накопление PR по-прежнему запрещено). Пока собственный PR не смержен — новый не открываем. Мерж-очередь: перед каждым мержем `git fetch`, база подмержена, тесты зелёные.
- Контрибьютор-переводчик (с 11.11): работает по `CONTRIBUTING.md` (tracked); скоуп — только Value в `ru.json` + текст QRC в `*-LOC.txt`; апрув/мерж его PR — только по слову человека; diff его тестов смотреть лично (не ослабил ли ассёрты).
- MUST: разделение ключей при парной работе (решение 11.11, схема «новые vs существующие»). Владелец `en.json` — только основной работник: новые ключи (`agoText`, SYNC-карта, `IN USE`, `Test Room` и далее) добавляет лишь он парой `en.json` + `ru.json` + тест. Переводчик правит только Value СУЩЕСТВУЮЩИХ ключей в `ru.json` (+ ассёрт в том же коммите); добавлять/переименовывать/удалять ключи, трогать `en.json` — запрещено. Пересечение по ключам = стоп и вопрос человеку до кода.
- MUST: мерж-очередь при парной работе. Перед стартом ветки — `git fetch origin`, база — свежий `dev`. В описание PR — явный список ключей (новые `table:key` либо `ключ: «старое» → «новое»`). Мерж строго по одному: второй ждёт пока первый смержен и база подмержена, потом `npm test` зелёный. Конфликт по `ru.json`/`en.json` — не резолвить молча: стоп, сверить чей ключ новее, переразвести множества.
- MUST: гигиена веток и PR (чтоб ничего не сломать). Висяков ноль: смерженную ветку удаляем сразу и локально, и на remote (`git branch -d` + `git push origin --delete`); закрытый без мержа PR = ветка-покойник — проверяем, что содержимое поглощено, и удаляем. Перед каждым мержем: `git fetch`, база подмержена, тесты зелёные, `git branch --merged dev` — лишнего не держим. Чужие несмерженные ветки не трогаем и не удаляем без слова человека.
- MUST NOT: мержить «пачкой вслепую». Каждый мерж — по слову человека (G4 из `todo.md`); force-push запрещён всегда.
- `todo.md` (локальный, в git не едет): после каждой завершённой работы отметить сделано/не сделано, иначе план врёт.
